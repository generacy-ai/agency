# Feature Specification: Add mcpCommand Field to ContainerConfig Schema

**Branch**: `136-containerconfig-type-src-types` | **Date**: 2026-01-26 | **Status**: Draft

## Summary

The `ContainerConfig` type in `packages/agency-extension/src/types/container.ts` defines an optional `mcpCommand` field, but this field is not present in the Zod schema `ContainerConfigSchema` in `packages/agency-extension/src/config/ConfigSchema.ts`. This inconsistency prevents users from configuring custom MCP server commands through the configuration system.

This feature adds the missing `mcpCommand` and `mcpArgs` fields to the Zod schema, updates the TypeScript type to include `mcpArgs`, and modifies `McpClientService._doConnect()` to use these fields when connecting to containers.

## User Stories

### US1: Configure Custom MCP Server Command

**As a** developer using dev containers,
**I want** to configure a custom MCP server command and arguments per container,
**So that** I can connect to MCP servers that don't use the default `npx @modelcontextprotocol/server` command.

**Acceptance Criteria**:
- [ ] Container configuration accepts `mcpCommand` as an optional string field
- [ ] Container configuration accepts `mcpArgs` as an optional array of strings
- [ ] Configuration is validated by Zod schema
- [ ] McpClientService uses configured command/args when connecting

### US2: Use Default Command When Not Configured

**As a** developer,
**I want** the MCP connection to fall back to the default command when `mcpCommand` is not configured,
**So that** existing configurations continue to work without modification.

**Acceptance Criteria**:
- [ ] When `mcpCommand` is not set, default to `npx @modelcontextprotocol/server`
- [ ] Existing container configurations without `mcpCommand` still work
