## Summary

`auto.md`'s D.3 request-changes path (and `review.md`) contract says: *"post a COMMENT-event PR review with per-finding inline comments — the PR feedback monitor's existing thread signal drives the fix loop."* On the snappoll run, both request-changes reviews were posted as a **single top-level COMMENT review body with zero inline threads** (`reviewThreads(first:30)` on PR #14 returns empty). The server-side feedback loop (generacy#861/#869/#878/#883 lineage) keys on *thread* signals, so posting bodies instead of threads quietly disconnects the loop the contract depends on — and there are no per-finding resolution states for the re-review to check.

## Evidence (christrudelpw/snappoll PR #14)

- 2026-07-14T22:07:46Z — review 1 (`generacy-ai`, COMMENTED): one body containing "3 blocking findings" as markdown sections. No inline comments.
- 2026-07-14T22:49:54Z — review 2 (COMMENTED): "previous request-changes findings are not actually resolved", again one body, no threads.
- GraphQL: `pullRequest(number:14).reviewThreads` → empty.
- Outcome: the round-2 instructions (`git rm -r --cached node_modules .env`) were never executed by any agent; the operator ran them by hand at 23:15:43.

## Suggested fix

In the shared review-verdict flow (auto.md D.2/D.3 + review.md request-changes step):

1. Post request-changes as a review whose **findings are inline comments** (`gh api` review with `comments[]` carrying path/line per finding), falling back to a body-level comment only for findings without a file anchor (and say so in the body).
2. Keep the marked body as the summary, but each finding becomes a resolvable thread the feedback monitor and re-review can key on.
3. Re-review step: check thread resolution state per finding instead of re-deriving everything from the diff.

Note this interacts with the gate-race bug filed on generacy from the same run (server-side flow advancing `implementation-review` after a request-changes review): fixing threads alone won't hold the gate, and fixing the gate alone leaves the fix loop blind. Both are needed.
