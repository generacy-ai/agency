# Research: Core Telemetry Capture

## Technology Decisions

### Event Bus Implementation: Node.js EventEmitter

**Decision**: Use Node.js built-in `EventEmitter` for internal event distribution.

**Rationale**:
- Zero additional dependencies
- Well-understood, battle-tested API
- Supports both sync and async listeners
- Sufficient for internal pub/sub pattern

**Alternatives Considered**:
- **Custom Observable pattern**: More flexibility but unnecessary complexity
- **External library (mitt, eventemitter3)**: Additional dependency for minimal benefit
- **RxJS**: Overkill for simple event distribution

### Handler Interception: Function Wrapper Pattern

**Decision**: Wrap existing tool handlers with a higher-order function.

**Rationale**:
- Non-invasive to existing code
- Works with any handler signature
- Easy to test in isolation
- Preserves original handler behavior

**Implementation Pattern**:
```typescript
function wrapToolHandler<T, R>(
  handler: (request: T) => Promise<R>,
  telemetry: TelemetryBus,
  config: TelemetryConfig
): (request: T) => Promise<R> {
  return async (request) => {
    const startTime = performance.now();
    try {
      const result = await handler(request);
      emitSuccess(telemetry, request, result, startTime);
      return result;
    } catch (error) {
      emitError(telemetry, request, error, startTime);
      throw error; // Re-throw to preserve behavior
    }
  };
}
```

### Schema Versioning: Zod with .passthrough()

**Decision**: Use Zod schemas with versioned naming and `.passthrough()`.

**Rationale**:
- Type-safe runtime validation
- Forward-compatible with unknown fields
- Easy version migration path
- Aligns with `@generacy-ai/contracts` future adoption

**Pattern**:
```typescript
export const ToolCallEventV1 = z.object({
  // ... fields
}).passthrough();

// Future: ToolCallEventV2 extends or replaces
export const ToolCallEvent = ToolCallEventV1;
```

### Fire-and-Forget Recording

**Decision**: Don't await provider `record()` calls.

**Rationale**:
- Critical for <5ms overhead requirement
- Telemetry should never block tool execution
- Provider failures are logged but don't propagate

**Implementation**:
```typescript
// Fire-and-forget pattern
providers.forEach(provider => {
  provider.record(event).catch(err => {
    logger.warn(`Telemetry provider ${provider.name} failed:`, err);
  });
});
```

### Error Isolation Per Provider

**Decision**: Wrap each provider call in try-catch.

**Rationale**:
- One failing provider doesn't affect others
- Aligns with "log warning and continue" design decision
- Maintains system stability

## MCP SDK Integration Research

### Tool Handler Registration

The MCP SDK provides two APIs for tool handling:

1. **Low-level**: `server.setRequestHandler(CallToolRequestSchema, handler)`
2. **High-level**: `mcpServer.tool('name', schema, handler)`

Both can be wrapped at the handler level without modifying SDK internals.

### Handler Signature

```typescript
// Low-level handler receives full request
type LowLevelHandler = (
  request: CallToolRequest,
  extra: RequestHandlerExtra
) => Promise<CallToolResult>;

// High-level handler receives parsed args
type HighLevelHandler<T> = (
  args: T,
  extra: RequestHandlerExtra
) => Promise<{ content: Content[] }>;
```

### Session Context Access

The `extra` parameter provides:
- `sessionId`: Unique session identifier
- `authInfo`: Authentication context
- `sendNotification`: For server-to-client messages

We capture `sessionId` in telemetry events when available.

## Implementation Patterns

### Timing Measurement

Use `performance.now()` for high-resolution timing:

```typescript
const startTime = performance.now();
// ... execute handler
const durationMs = performance.now() - startTime;
```

### UUID Generation

Use `crypto.randomUUID()` (Node.js 14.17+):

```typescript
import { randomUUID } from 'node:crypto';
const eventId = randomUUID();
```

### Privacy-Aware Data Capture

Conditional inclusion based on config:

```typescript
const event: ToolCallEvent = {
  id: randomUUID(),
  timestamp: new Date().toISOString(),
  toolName,
  serverName,
  durationMs,
  success,
  ...(config.captureInputs && { inputs }),
  ...(config.captureOutputs && { outputs }),
};
```
