# Research: MCP Server Foundation

## Technology Decisions

### MCP SDK Architecture

The `@modelcontextprotocol/sdk` provides two server abstractions:

1. **`McpServer`** (high-level)
   - Simple `registerTool()` API with Zod schemas
   - Automatic request/response handling
   - No hook for tool list filtering

2. **`Server`** (low-level)
   - Manual `setRequestHandler()` for each schema
   - Full control over request/response cycle
   - Required for mode-based filtering

**Decision**: Use low-level `Server` for mode filtering control.

### Tool Registration Pattern

The MCP SDK expects tools in this format:

```typescript
{
  name: string;
  description: string;
  inputSchema: {
    type: 'object';
    properties: Record<string, JsonSchema>;
    required?: string[];
  };
}
```

Agency extends this with:
- `namespace` - for mode filtering
- `outputPattern` - for terse output
- `modes` - explicit mode list (optional)

## Alternatives Considered

### Alternative 1: McpServer with Post-Filter

```typescript
const server = new McpServer({ name: 'agency', version: '1.0.0' });
// Register all tools
// Problem: No way to filter in tools/list response
```

**Rejected**: No filtering hook available.

### Alternative 2: Proxy Pattern

```typescript
class AgencyServer {
  private mcpServer: McpServer;
  // Intercept all calls
}
```

**Rejected**: Over-engineered, MCP Server is already thin.

### Alternative 3: Custom Protocol

Build MCP protocol handling from scratch.

**Rejected**: Reinventing the wheel, SDK is well-maintained.

    const sources = [
      this.loadFile('.agency/config.json'),

### Tool Registry Pattern

```typescript
class ToolRegistry {
  private tools = new Map<string, AgencyTool>();

  register(tool: AgencyTool): void {
    this.tools.set(tool.name, tool);
  }

  getForMode(mode: string): AgencyTool[] {
    const patterns = this.modes.get(mode) ?? [];
    return [...this.tools.values()].filter(t =>
      patterns.some(p => minimatch(t.name, p))
    );
  }
}
```

### Plugin Lifecycle Pattern

```typescript
class PluginLoader {
  async load(plugin: AgencyPlugin): Promise<void> {
    if (plugin.initialize) await plugin.initialize();
    for (const tool of plugin.tools) {
      this.registry.register(tool);
    }
    this.loaded.push(plugin);
  }

  async unloadAll(): Promise<void> {
    for (const plugin of this.loaded.reverse()) {
      if (plugin.shutdown) await plugin.shutdown();
    }
  }
}
```

## Security Considerations

1. **Config file loading**: Only load from project root, never from arbitrary paths
2. **Plugin loading**: Plugins run with full Node.js privileges
3. **Tool execution**: Validate input against schema before execution

## Performance Considerations

1. **Startup time**: Lazy-load plugins if not immediately needed
2. **Tool filtering**: Pre-compute filtered tool lists on mode change
3. **Memory**: Clear tool list cache on mode switch
