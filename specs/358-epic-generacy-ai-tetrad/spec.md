## Clarifications

Resolved in [clarifications.md](./clarifications.md) Batch 1 (2026-06-29). Summary of decisions that bind implementation:

- **Q1 — Manifest file**: The (speckit) manifest is `specs/<branch>/tasks.md`. Task blocks are the existing `## Task: <id>` sections. The filed issue number is recorded as a `**Issue**: #<n>` line inside each task block, and the parent epic issue as `**Epic**: #<n>` at the top of `tasks.md`. This is distinct from the **epic** manifest `.generacy/epics/<slug>.yaml` maintained by `generacy cockpit manifest sync` (#790) — the two should not be conflated.
- **Q2 — Engine handoff**: `tasks_to_issues` and `manifest sync` communicate **via artifacts, not a JSON pipe**. `tasks_to_issues` writes the new issue numbers into `tasks.md` and the epic body checklist; `generacy cockpit manifest sync <epic-ref>` then re-parses the epic body (per #790) to update the `.yaml`. A tempfile passed as `--from <path>` is the documented fallback only if a direct handoff is later required.
- **Q3 — Partial re-run reconciliation**: On a partial manifest (some task blocks already numbered), `/cockpit:file` files only the task blocks lacking a number, reuses the recorded parent epic, then runs `manifest sync`. Partial states recover by re-running the same command — no duplicates (satisfies US2-AC3).
- **Q4 — Epic argument purpose**: The optional epic argument is an **existing parent epic to reuse** (for recovery/idempotency). Default (no arg) creates a new parent. Separately, the `spec.md` `**Epic**:` line (the meta-epic, e.g. `generacy-ai/tetrad-development#85`) is recorded as a `Parent epic:` link in the new parent issue's body. The argument is **not** a cross-repo target override — Out of Scope stands.
- **Q5 — Parent-epic recovery after partial failure**: Engine-side idempotency. `tasks_to_issues` detects an already-created parent by title or hidden HTML marker and reuses it, preventing duplicate parents. `/cockpit:file` does not maintain sidecar state for this.
