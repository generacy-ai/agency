## Task

Modify the orchestrator to request execution leases from the cloud before dispatching work to workers.

### Changes

**Before dispatching to a worker:**
1. Send `lease_request` to cloud via relay with `{ queueItemId, jobId }`
2. Wait for response: `lease_granted` or `lease_denied`
3. On `lease_granted` → dispatch to worker, store `leaseId` with the active job
4. On `lease_denied` (reason: `at_capacity`) → leave item in queue, do not dispatch

**On workflow pause/complete/fail/cancel:**
1. Send `lease_release` to cloud via relay with `{ leaseId }`
2. Clear stored lease association

**Heartbeat loop:**
1. Every 30 seconds, send `lease_heartbeat` for each active lease
2. If heartbeat fails (lease expired/not found), treat as if lease was denied — pause execution gracefully

**Listen for `slot_available` push:**
1. When cloud pushes `slot_available`, check local queue for pending items
2. If items exist, attempt `lease_request` for the highest-priority item

### Relay Message Types

| Message | Direction | Payload |
|---------|-----------|---------|
| `lease_request` | Cluster → Cloud | `{ queueItemId, jobId }` |
| `lease_granted` | Cloud → Cluster | `{ leaseId, ttlSeconds }` |
| `lease_denied` | Cloud → Cluster | `{ reason: 'at_capacity' }` |
| `lease_release` | Cluster → Cloud | `{ leaseId }` |
| `lease_heartbeat` | Cluster → Cloud | `{ leaseId }` |
| `slot_available` | Cloud → Cluster | `{ orgId, availableSlots: number }` |

### Acceptance Criteria

- [ ] Orchestrator requests lease before dispatching work
- [ ] Orchestrator releases lease on pause/complete/fail/cancel
- [ ] Heartbeat loop running for all active leases
- [ ] `slot_available` listener triggers dispatch attempts
- [ ] Graceful handling when lease is denied (item stays queued)
- [ ] Graceful handling when heartbeat fails (lease expired)
- [ ] Unit tests for lease request/release/heartbeat flows
