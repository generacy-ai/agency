# Research: Git Utilities Implementation

## Technology Decisions

### simple-git Library

**Decision**: Use `simple-git` (^3.30.0) for git operations

**Rationale**:
- Well-maintained library with 3M+ weekly downloads
- TypeScript support with full type definitions
- Promise-based API matches our async/await patterns
- Already used in agency-plugin-spec-kit
- Provides abstraction over git CLI commands

**Alternatives Considered**:
1. **isomorphic-git** - Pure JS implementation, but heavier and slower
2. **nodegit** - Native bindings, complex installation, not ESM-friendly
3. **Raw exec/spawn** - More control but requires parsing git output

### API Design Pattern

**Decision**: Standalone async functions with optional `cwd` parameter

**Rationale**:
- Matches existing patterns in agency codebase
- Each function is independently testable
- No shared state or class instances to manage
- Default to `process.cwd()` for convenience

**Alternative**: Object-oriented with GitManager class
- Rejected because it adds complexity without benefits
- Would require managing instance lifecycle
- Functions are stateless by nature

### Error Handling

**Decision**: Throw errors with descriptive messages

**Rationale**:
- Consistent with spec clarification decisions
- Errors are easier to catch and handle at call site
- No ambiguity about null/undefined return values
- Enables better error logging and debugging

## Implementation Patterns

### SimpleGit Instance Creation

```typescript
export async function getGit(cwd?: string): Promise<SimpleGit> {
  const workDir = cwd ?? process.cwd();
  if (!(await isGitRepo(workDir))) {
    throw new Error(`Not a git repository: ${workDir}`);
  }
  return simpleGit(workDir);
}
```

Key points:
- Validate repository before returning instance
- Use nullish coalescing for cleaner default handling
- Return promise for consistency with other functions

### Branch Existence Check Pattern

```typescript
// Check local branches first (faster)
const localBranches = await git.branchLocal();
if (localBranches.all.includes(name)) return true;

// Then check remote (origin/)
const remoteBranches = await git.branch(['-r']);
return remoteBranches.all.includes(`origin/${name}`);
```

This two-step approach:
1. Checks local branches first (most common case)
2. Falls back to remote only if not found locally
3. Assumes 'origin' as the default remote

### Status Mapping

simple-git's StatusResult → our GitStatus:
```typescript
{
  isClean: status.isClean(),
  currentBranch: await getCurrentBranch(cwd),
  hasChanges: !status.isClean()
}
```

Note: `isClean` and `hasChanges` are inverses for clarity in different contexts.

## Edge Cases

### Detached HEAD State
- `getCurrentBranch()` returns "HEAD" in detached state
- This is correct behavior per git rev-parse

### Non-existent Remote
- `branchExists()` will fail if origin remote doesn't exist
- Consider catching and returning false for remote check

### Empty Repository
- All branch operations may fail in empty repo
- `getStatus()` should still work
