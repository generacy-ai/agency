# Implementation Plan: C5 Template File Definitions and Defaults

**Feature**: Define default template files and template resolution logic for spec-kit
**Branch**: `159-c5-template-file-definitions`
**Status**: Complete

## Summary

This feature creates a centralized template management system for spec-kit. It introduces a `src/templates/` module that:
1. Defines TypeScript types for all template types
2. Provides embedded default content for each template (derived from existing `.specify/templates/` files)
3. Implements template resolution that checks custom paths first, then falls back to defaults
4. Supports variable substitution during template copy operations
5. Refactors `copy-template.ts` to use the new template definitions as the single source of truth

## Key Design Decisions

### 1. Template Definition Structure

Each template is defined with:
- `type`: The template type identifier
- `defaultFilename`: The filename when copied
- `defaultContent`: Embedded default content (multi-line string)
- `destSubdir`: Optional subdirectory (e.g., 'checklists' for checklist template)
- `sourceFile`: Name of source file in templates directory (for custom templates)

### 2. Resolution Priority

1. Check `config.paths.templates` directory for custom template file
2. Fall back to embedded `defaultContent`

This allows users to customize templates while providing sensible defaults out of the box.

### 3. Variable Substitution

Variables use mustache-style `{{variable}}` syntax:
- `{{feature_name}}` - Feature name from branch
- `{{description}}` - Feature description
- `{{date}}` - Current date (ISO format)
- `{{branch}}` - Full branch name

Substitution happens during `copy_template` operation, not during resolution.

### 4. Integration with copy-template.ts

The existing `TEMPLATE_MAPPINGS` in `copy-template.ts` will be removed. Instead:
- Import `TEMPLATES` from `templates/index.ts`
- Use `resolveTemplate()` to get content (with custom/default fallback)
- Use `substituteVariables()` to apply variable substitution
- Use template definition's `destSubdir` and `defaultFilename` for destination logic
