## Summary

## Problem

Every repository using speckit workflows must maintain its own copies of `speckit-feature.yaml` and `speckit-bugfix.yaml` in `.generacy/`. Across 7+ repos, these files drift out of sync (we just found 3 different versions in the wild — v1.0.0, v1.1.0, and v1.2.0). Any workflow improvement requires manually updating every repo.

## Proposed Solution

Bundle canonical workflow YAML files inside the `agency-plugin-spec-kit` package so they ship automatically with plugin updates.

### Implementation

1. **Add `workflows/` directory to the spec kit plugin package:**
   ```
   packages/agency-plugin-spec-kit/
   ├── src/
   ├── workflows/
   │   ├── speckit-feature.yaml    # canonical feature workflow
   │   └── speckit-bugfix.yaml     # canonical bugfix workflow
   └── package.json
   ```

2. **Export workflow paths from the package:**
   ```typescript
   // packages/agency-plugin-spec-kit/src/workflows.ts
   import { resolve, dirname } from 'node:path';
   import { fileURLToPath } from 'node:url';
   
   const __dirname = dirname(fileURLToPath(import.meta.url));
   
   export const BUILTIN_WORKFLOWS = {
     'speckit-feature': resolve(__dirname, '../workflows/speckit-feature.yaml'),
     'speckit-bugfix': resolve(__dirname, '../workflows/speckit-bugfix.yaml'),
   };
   ```

3. **Include `workflows/` in package.json `files` array** so they're published with the package.

4. **Register workflows with the generacy workflow resolver** (see companion issue in generacy repo) so the engine discovers them as fallbacks when no repo-local override exists.

### Outcome

- Repos that don't need workflow customization can delete their `.generacy/speckit-*.yaml` files entirely
- Workflow improvements ship automatically via plugin updates
- Single source of truth for the canonical workflows
