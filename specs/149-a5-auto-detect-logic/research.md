# Research: A5: Auto-detect logic for ticket refs

**Feature**: Ticket reference auto-detection
**Date**: 2026-02-01

## Technology Decisions

### 1. Detection Algorithm Design

**Decision**: Priority-based pattern matching with early exit

**Rationale**:
- URLs are most specific → check first
- Provider-specific patterns (Jira, Shortcut, LOCAL) → check second
- Ambiguous patterns (#123, bare numbers) → use default provider
- Early exit improves performance for common cases

**Alternatives Considered**:
- Parallel pattern matching with scoring (more complex, not needed)
- User-specified provider prefix (less user-friendly)

### 2. Pattern Specificity

**Decision**: Check Shortcut `sc-XXX` before Jira `PROJ-XXX`

**Rationale**:
- `SC-123` could match either Jira (two-letter project) or Shortcut
- Shortcut always uses `sc-` prefix, Jira projects vary
- Checking Shortcut first prevents false positives

### 3. LOCAL Pattern Format

**Decision**: Use `LOCAL-NNN` format (case-insensitive)

**Rationale**:
- Mirrors Jira format for consistency
- `LOCAL` prefix is unambiguous (won't conflict with real Jira projects)
- Case-insensitive allows `local-001` and `LOCAL-001`

## Performance Considerations

- Regex compilation happens once (module load)
- Early exit on match minimizes pattern checks
- Most common inputs (URLs, #123) are checked early
- No external dependencies or network calls
