# Research: Static Assets & Icons

## Technology Decisions

### Icon Format: SVG

**Decision**: Use inline SVG with `currentColor` for strokes

**Rationale**:
- SVG scales perfectly at any size/zoom level
- `currentColor` automatically adapts to VS Code theme colors
- Inline SVG (not PNG) allows runtime color adaptation
- Small file size (~200-600 bytes per icon)

**Alternatives Considered**:
- PNG icons: Would require separate light/dark variants, doesn't scale
- Icon fonts: More complex setup, harder to maintain individual icons
- Codicons (VS Code built-in): Limited set, doesn't cover our domain-specific needs

**References**:
- [VS Code Icon Theme Guide](https://code.visualstudio.com/api/extension-guides/icon-theme)
- [Product Icon Contribution](https://code.visualstudio.com/api/references/contribution-points#contributes.icons)

### Styling: VS Code CSS Variables

**Decision**: Use VS Code's built-in CSS variables for all webview styles

**Rationale**:
- Automatic theme adaptation (light/dark/high-contrast)
- Consistent with VS Code UI/UX
- No manual color management needed
- Accessibility built-in (high-contrast support)

**Alternatives Considered**:
- Custom CSS variables: Would break theme integration
- Tailwind CSS: Overkill for simple webviews, adds build complexity
- CSS-in-JS: Not suitable for webview content security policy

**References**:
- [VS Code Webview Theming](https://code.visualstudio.com/api/extension-guides/webview#theming-webview-content)
- [VS Code CSS Variables Reference](https://code.visualstudio.com/api/references/theme-color)

## Implementation Patterns

### Icon Design System

**Stroke-based Line Icons**:
- Consistent stroke-width: 1.5px
- Rounded line caps and joins
- 24x24 viewBox (standard icon size)
- Simple, recognizable shapes

**Example Structure**:
```svg
<svg xmlns="http://www.w3.org/2000/svg"
     viewBox="0 0 24 24"
     fill="none"
     stroke="currentColor"
     stroke-width="1.5"
     stroke-linecap="round"
     stroke-linejoin="round">
  <!-- Icon content -->
</svg>
```

### CSS Architecture

**BEM-inspired Naming** (without strict BEM):
- Component-based classes (`.button`, `.input`, `.badge`)
- Modifier classes (`.button-primary`, `.button-secondary`)
- Utility classes (`.mt-1`, `.p-2`, `.flex`)

**Layered Structure**:
1. Reset & base styles
2. Layout utilities
3. Typography scale
4. Component styles
5. Utility classes

## Key Learnings

### VS Code Theme Integration

**Critical**: Always use VS Code CSS variables, never hardcode colors:
```css
/* ✓ Correct */
color: var(--vscode-foreground);
background: var(--vscode-editor-background);

/* ✗ Wrong */
color: #333;
background: white;
```

### Icon Color Inheritance

**Critical**: Use `stroke="currentColor"` to inherit theme colors:
```svg
<!-- ✓ Correct -->
<svg stroke="currentColor">...</svg>

<!-- ✗ Wrong -->
<svg stroke="#000">...</svg>
```

### Webview Content Security Policy

**Note**: The webview.css must be loaded via webview's `asWebviewUri()` API.
Inline styles may be blocked by CSP in strict mode.
