## Task

Cap the effective worker count at the minimum of the configured worker count and the subscription tier's concurrent execution limit.

### Behavior

```
effectiveWorkers = min(configuredWorkers, tierLimit)
```

- The orchestrator should fetch the tier limit from the cloud (via relay or cached from subscription data) on startup and when the subscription changes
- If `configuredWorkers > tierLimit`, only `tierLimit` worker containers should be actively used
- The orchestrator should NOT scale up beyond `configuredWorkers` — the local config reflects resource constraints or developer preference
- When the tier limit changes (upgrade/downgrade), adjust effective workers accordingly

### Handle `cluster_rejected`

- If the relay connection is rejected with `cluster_rejected` (cluster limit reached), surface a clear error to the developer
- Include the current limit and suggest upgrading

### Acceptance Criteria

- [ ] Effective worker count capped at `min(configured, tierLimit)`
- [ ] Tier limit fetched on startup and cached
- [ ] Tier limit updated on subscription change notification
- [ ] `cluster_rejected` handled with user-facing error message
- [ ] Unit tests for auto-scale-down logic
