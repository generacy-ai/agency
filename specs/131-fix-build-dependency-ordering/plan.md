# Implementation Plan: Fix Build Dependency Ordering

**Feature**: Fix build dependency ordering for agency-plugin-git
**Branch**: `131-fix-build-dependency-ordering`
**Status**: Complete

## Summary

The build fails because Turborepo's `^build` operator only considers `dependencies` and `devDependencies` for build ordering—**peer dependencies are ignored**. All plugins have `@generacy-ai/agency` as a `peerDependency` only, so they build in parallel with the core package instead of after it.

## Root Cause Analysis

1. **turbo.json is correct**: Has `"dependsOn": ["^build"]` which should order builds by workspace dependencies
2. **Plugins use peerDependencies**: `agency-plugin-git` has `"@generacy-ai/agency": "workspace:*"` as `peerDependencies`
3. **Turbo ignores peerDependencies**: The `^` operator only looks at `dependencies` and `devDependencies`
4. **Result**: All plugins build in parallel with core, failing when they try to import types that don't exist yet

## Technical Context

- **Language**: TypeScript 5.x
- **Build Tool**: Turborepo 2.7.5
- **Package Manager**: pnpm with workspaces
- **Affected Packages**:
  - `@generacy-ai/agency-plugin-git`
  - `@generacy-ai/agency-plugin-npm`
  - `@generacy-ai/agency-plugin-docker`
  - `@generacy-ai/agency-plugin-firebase`
  - `@generacy-ai/agency-plugin-humancy`

## Solution

Add `@generacy-ai/agency` to `devDependencies` in each plugin package.json while keeping it in `peerDependencies`. This is the standard pattern for TypeScript monorepos:

- **peerDependencies**: Declares runtime requirement (consumer must provide it)
- **devDependencies**: Enables build-time resolution and Turborepo ordering
