# Feature Specification: Part of the **Cockpit Remote Gates** epic — a central operator inbox on generacy

**Branch**: `449-part-cockpit-remote-gates` | **Date**: 2026-07-22 | **Status**: Draft

## Summary

Part of the **Cockpit Remote Gates** epic — a central operator inbox on generacy.ai for answering `/cockpit:auto` human gates so the driving session never blocks. Epic tracking issue: generacy-ai/generacy-cloud (see epic for phase ordering). Full design and **wire contracts** (gate record, answer NDJSON line, outcome ack, gateId/generation rules): [cockpit-remote-gates-plan.md](https://github.com/generacy-ai/tetrad-development/blob/develop/docs/cockpit-remote-gates-plan.md). Implement against the contracts as written; propose contract changes on the epic before diverging.

## Context

The skill-side rework: in UI-gates mode, `/cockpit:auto` never blocks on a human gate — it opens a remote gate record and keeps dispatching, applying answers when they arrive as `gate-answer` events on the existing wake paths.

## Scope

`packages/claude-plugin-cockpit/commands/auto.md` (+ plugin docs):

- New invocation flag `--gates=ui|local|auto` (default `auto`: use UI gates when `cockpit_gate_open` is present and the cluster is cloud-activated, else local). `--gates=local` preserves today's behavior exactly.
- UI mode: every gate contract G.1–G.7 calls `cockpit_gate_open` with the gate mapped to the wire contract (same drafted body/options the AskUserQuestion path shows today; generation per the plan-doc rules), prints a one-line pointer (`gate open: <title> → answer in the generacy.ai inbox`), records the open gate in session state, and returns to the dispatch loop.
- New dispatch class **D.12 `gate-answer`** in the event dispatch table (doorbell NDJSON line and `cockpit_await_events` batch item): validate the gate is still current against live labels/state — if stale, `cockpit_gate_ack` with `superseded`; otherwise map `optionId`/`freeText` onto the exact same handling the corresponding AskUserQuestion selection performs today (relay clarify answers, advance, queue, merge, fixer spawn, mute, exit, edit-directive loops via freeText — revised drafts re-open as a new generation), then ack `applied` (or `failed` with detail).
- Fallback semantics: `cockpit_gate_open` error → local AskUserQuestion for that gate (fail toward the operator, never stall); repeated failures noted once, loop continues.
- Startup sweep in UI mode re-opens gates for pending `waiting-for:*` states (idempotent by gateId).
- **Re-pin the playbook-verification tests** for every auto.md edit — update pins, do not weaken them.

## Out of scope

Cluster/cloud implementation (P1–P3); dual-surface first-answer-wins; per-gate auto-approve.

## Acceptance criteria

- Playbook-verification suite green with updated pins; `--gates=local` byte-path unchanged; UI-mode contracts (gate mapping table, D.12, fallback, supersession) specified unambiguously in auto.md.
