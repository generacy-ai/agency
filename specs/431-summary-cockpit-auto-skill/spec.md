## Summary

The `/cockpit:auto` skill arms a **second, redundant poll loop** against the epic on top of the one `cockpit_await_events` already runs, doubling background GraphQL polling and contributing to GitHub GraphQL rate-limit exhaustion during auto runs.

This is the skill-side half of a cross-repo issue. The engine-side analysis and the other fixes live in **generacy-ai/generacy#970**.

## Detail

`packages/claude-plugin-cockpit/commands/auto.md` arms two things per run:

1. **`generacy cockpit watch <epic-ref>`** as a background Monitor "doorbell" sensor (`auto.md:43`). Although the parent treats its stdout as a doorbell only (never parses content), the subprocess still runs a **full poll loop** — `runOnePoll` + `resolveEpic` every 30s, each cycle doing `gh issue view` + per-PR `gh pr checks` (all GraphQL-backed).
2. **`cockpit_await_events`** on every wake (`auto.md:79`), whose event-bus registry spins up **its own** full poll loop in the MCP server process.

So the same epic is polled by two independent 30s loops that don't know about each other — a flat 2× on background GraphQL cost, continuous even when the epic is idle.

Additionally, the loop re-checks live state via `cockpit_status(json=true)` on **every** actionable event (`auto.md:85`); each such call is a full per-ref GraphQL fan-out on the generacy side. That amplifier is tracked in the generacy issue, but the dispatch cadence that triggers it is defined here.

## Proposed fix

Once generacy exposes a single shared poll signal (a doorbell emitted by the same event-bus poll loop that `cockpit_await_events` drains), drop the separate `generacy cockpit watch` subprocess from the auto skill so only one poll loop exists per epic. Coordinate with the generacy companion issue — the doorbell mechanism has to land engine-side first.

Consider also whether the per-event `cockpit_status` re-check can be reduced (e.g., trust the batched event's carried state for a subset of dispatch classes, or debounce re-checks within a coalesce window) without violating the "live state is authoritative" contract.
