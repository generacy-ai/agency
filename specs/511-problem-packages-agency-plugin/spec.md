# Feature Specification: Redirect /plan step 5 from CLAUDE.md to specs/<feature>/stack.md

**Branch**: `511-problem-packages-agency-plugin` | **Date**: 2026-08-28 | **Status**: Draft
**Issue**: [generacy-ai/agency#511](https://github.com/generacy-ai/agency/issues/511)

## Summary

The `/plan` slash command playbook — shipped in two byte-identical copies at
`packages/agency-plugin-spec-kit/commands/plan.md` and
`packages/claude-plugin-agency-spec-kit/commands/plan.md` — instructs the agent in
step 5 to call the `update_agent` MCP tool and write new technology info into the
repo-root `CLAUDE.md`. Because Generacy cluster workers copy these `commands/*.md`
files verbatim into `~/.claude/commands/` and run the bare `/plan` command, every
feature branch's plan phase writes per-feature, transient content into `CLAUDE.md`.

This bloats `CLAUDE.md` (observed ~285 KB / ~71K tokens in one run), causes repeated
merge conflicts between sibling branches, and — when `update_agent` is unavailable —
prompts the model to hand-write freeform planning narratives into `CLAUDE.md`, which
is worse than the tool's bounded output.

The fix rewrites step 5 so the plan phase writes per-feature technical context to
`specs/<feature>/stack.md` and never touches repo-root agent-context files, then adds
a pin test guarding against regression. The `update_agent` tool itself and the
`constitution.md` sync step are left untouched (those write durable conventions).

## User Stories

### US1: Plan phase writes tech context to the feature directory (Primary)

**As a** Generacy cluster worker (or a developer running `/plan` locally),
**I want** the plan phase to record per-feature technical context in
`specs/<feature>/stack.md`,
**So that** transient, feature-scoped planning notes stay isolated to the feature
branch instead of accumulating in and conflicting over the repo-root `CLAUDE.md`.

**Acceptance Criteria**:
- [ ] Step 5 of both `plan.md` copies instructs writing `specs/<feature>/stack.md`.
- [ ] `stack.md` begins with the header line `Generated by /plan — do not hand-edit.`
      followed by language / framework / dependencies / notable decisions.
- [ ] Step 5 explicitly states the plan phase must NEVER modify repo-root
      agent-context files (`CLAUDE.md`, `AGENTS.md`, `GEMINI.md`,
      `.github/copilot-instructions.md`).

### US2: Regression is caught automatically

**As a** maintainer of the spec-kit packages,
**I want** a pin test that fails if step 5's old behavior is reintroduced or the two
`plan.md` copies drift apart,
**So that** the fix from generacy#899 cannot silently regress.

**Acceptance Criteria**:
- [ ] A pin test asserts neither `plan.md` copy mentions `CLAUDE.md`,
      `update_agent`, or "agent context".
- [ ] The pin test asserts the two `plan.md` copies remain byte-identical.
- [ ] The pin test fails if the old step 5 is restored.

### US3: The update_agent tool remains available and correct

**As a** consumer of the `constitution.md` sync workflow,
**I want** the `update_agent` MCP tool and its existing tests left untouched,
**So that** durable convention sync (a legitimate use) continues to work.

**Acceptance Criteria**:
- [ ] The `update_agent` tool implementation is unchanged.
- [ ] `packages/agency-plugin-spec-kit/tests/tools/update-agent.test.ts` still passes.
