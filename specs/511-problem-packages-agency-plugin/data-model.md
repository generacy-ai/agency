# Data Model: /plan step 5 redirect

No runtime types change. The "entities" here are file contracts and test-time
structures.

## Entities

### PlanCommandFile

The `/plan` playbook markdown. Two instances, required identical.

| Field | Value |
|-------|-------|
| canonicalPath | `packages/agency-plugin-spec-kit/commands/plan.md` |
| mirrorPath | `packages/claude-plugin-agency-spec-kit/commands/plan.md` |
| invariant | `read(canonicalPath) === read(mirrorPath)` (byte-identical) |

### StackFile (produced at /plan runtime, per feature)

| Field | Rule |
|-------|------|
| path | `specs/<feature>/stack.md` |
| firstLine | exactly `Generated by /plan — do not hand-edit.` |
| body | language, framework, dependencies, notable technical decisions |
| writeMode | full overwrite on every `/plan` run (never append) |

### ProhibitionSentence

The single sentence in step 5 permitted to contain agent-context filenames.

| Field | Rule |
|-------|------|
| text | names `CLAUDE.md`, `AGENTS.md`, `GEMINI.md`, `.github/copilot-instructions.md` literally |
| cardinality | exactly one occurrence per copy |
| scope rule | all matches of banned patterns B2/B3 (see contracts/plan-step5.md) must fall inside this sentence |

## Pin test structure (`tests/plan-command-pin.test.ts`)

```typescript
interface PinnedContract {
  presence: string[];        // P1–P4 from contracts/plan-step5.md
  bannedEverywhere: RegExp;  // /update[_-]?agent/i
  scopedBans: RegExp[];      // filename patterns + /agent[\s-]context/i
}
```

Validation algorithm per copy:
1. Assert each `presence` string is included.
2. Assert `bannedEverywhere` has zero matches.
3. Locate the prohibition sentence (by its pinned literal text); assert every match
   index of each `scopedBans` pattern falls within that sentence's [start, end) range.
4. Assert canonical bytes === mirror bytes.

## Relationships

- PlanCommandFile (both copies) contains exactly one ProhibitionSentence and the
  StackFile-producing instruction.
- The pin test depends on both PlanCommandFile instances and the pinned strings in
  `contracts/plan-step5.md`.
- The `update_agent` tool (`src/tools/update-agent.ts`) has **no** relationship to the
  new step 5 — it remains referenced only by `constitution.md`'s sync step.
