# Research: Redirect /plan step 5 to specs/<feature>/stack.md

## Background

generacy#899 attempted this fix in the Generacy prompt wrapper, but cluster workers
copy `commands/*.md` verbatim into `~/.claude/commands/` and run the bare `/plan`
command — the command markdown, not the wrapper, is the authoritative instruction
surface. The fix must land in the command files themselves.

Observed pathology: `CLAUDE.md` grew to ~285 KB / ~71K tokens; sibling feature branches
merge-conflict on it; when `update_agent` is unavailable the model hand-writes freeform
planning prose into `CLAUDE.md`, which is worse than the tool's bounded output.

## Decisions

### D1: Per-feature `stack.md`, not a trimmed CLAUDE.md section

**Decision**: write tech context to `specs/<feature>/stack.md`.
**Rationale**: per-feature content is transient and branch-scoped; `specs/<feature>/`
already holds all other per-feature artifacts, so conflicts between sibling branches
become structurally impossible (different directories).
**Alternatives considered**:
- Keep `update_agent` but bound its output — rejected: still one shared file, still
  conflicts, still accumulates.
- Drop the step entirely — rejected: tech context is useful downstream (tasks phase,
  implementers); it just belongs in the feature directory.

### D2: Overwrite on re-run (Q2)

**Decision**: `stack.md` is fully overwritten each `/plan` run.
**Rationale**: appending recreates the accumulating-log pathology in a new location;
the `Generated by /plan — do not hand-edit.` header declares command ownership;
`git log -p` recovers prior runs.

### D3: Explicit filenames in the prohibition (Q1)

**Decision**: the prohibition sentence names `CLAUDE.md`, `AGENTS.md`, `GEMINI.md`,
`.github/copilot-instructions.md` literally; the pin test scopes its absence checks
around that single sentence rather than requiring zero matches file-wide.
**Rationale**: the model hand-edits agent files precisely when instructions are vague —
explicitness is the mechanism. The issue's original zero-match grep criterion was
internally inconsistent with FR-003 and was amended by clarification Q1.

### D4: Positive + negative + identity pin assertions (Q3)

**Decision**: the pin test asserts presence of the new contract, scoped absence of the
old strings, and byte-identity of the two copies.
**Rationale**: absence-only assertions pass if step 5 is deleted wholesale (the #899
false-confidence failure mode). Matches repo pin philosophy (see
`packages/claude-plugin-cockpit/tests/playbook-verification.test.ts` and the CLAUDE.md
rule: re-pin, never weaken).

### D5: Pin test lives in `agency-plugin-spec-kit/tests/`, reads the mirror cross-package

**Decision**: single test file `tests/plan-command-pin.test.ts` in the canonical package
reads its own copy via `commandsDir` (or a relative path) and the mirror via
`../../claude-plugin-agency-spec-kit/commands/plan.md`.
**Rationale**: `claude-plugin-agency-spec-kit` has no `package.json`, no test runner,
and is deprecated — it cannot host tests. Cross-package relative reads from a monorepo
test are already precedented (cockpit tests read `commands/*.md` by path). The test
uses `node:fs` + `fileURLToPath(import.meta.url)` like `commands.test.ts`.

### D6: Regex for the hyphenated evasion

**Decision**: ban `/agent[\s-]context/i` outside the prohibition sentence.
**Rationale**: Q1 noted that the natural phrasing "agent-context files" (hyphenated)
would evade a literal "agent context" check while violating its intent.

### D7: Changeset names only `@generacy-ai/agency-plugin-spec-kit` (minor, Q4)

**Decision**: one changeset, minor bump, single package.
**Rationale**: changesets can only reference workspace packages with a `package.json`;
the mirror directory has none. Minor (not patch) because the plan phase stops producing
one user-visible output (CLAUDE.md updates) and starts producing another (`stack.md`).
