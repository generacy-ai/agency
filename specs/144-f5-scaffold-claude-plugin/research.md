# Research: Claude Code Plugin Structure

## Technology Decisions

### Plugin Type: Claude Code Slash Command Plugin

**Rationale**: Claude Code plugins use a simple markdown-based structure for defining slash commands. This allows rich command documentation and instructions without requiring compiled code.

### Source Reference: Existing Speckit Plugin

**Location**: `/workspaces/claude-plugins/plugins/speckit/`

The existing speckit plugin provides the command definitions that will be copied:
- 9 command files in `commands/` directory
- Plugin metadata in `.claude-plugin/plugin.json`

### MCP Dependency Architecture

The slash command plugin declares a dependency on the MCP server:
- **Plugin**: `claude-plugin-agency-spec-kit` (markdown commands)
- **MCP Server**: `@generacy-ai/agency-plugin-spec-kit` (TypeScript tools)

This separation allows:
1. Commands to be updated independently of tool implementations
2. Clear separation between user-facing instructions and backend logic
3. Reusability of MCP tools across different command plugins

## Alternatives Considered

### Alternative 1: Embedded MCP Server
Create a combined package with both commands and MCP server in one.

**Rejected because**:
- MCP server already exists as `agency-plugin-spec-kit`
- Violates separation of concerns
- Would duplicate existing functionality

### Alternative 2: Empty Placeholder Commands
Create command files with TODO markers only.

**Rejected because**:
- Per clarification Q1, user wants full content copied from source
- Placeholders provide no immediate value
- Would require additional work to fill in later

## Implementation Patterns

### Command File Structure
Each command markdown file follows this pattern:
```markdown
---
description: Short description of what the command does
arguments:
  - name: arg_name
    description: What the argument is for
    required: true/false
---

# Command Name

[Detailed instructions for Claude Code to execute]
```

### Plugin.json Structure
```json
{
  "name": "plugin-name",
  "version": "0.0.1",
  "description": "Plugin description",
  "requires": {
    "mcp": ["@scope/mcp-server-name"]
  }
}
```
