# Research: Terse Output Pattern Utilities

## Technology Decisions

### 1. Custom Type vs MCP SDK Type

**Decision**: Define custom `TerseToolResult` type, convert at MCP boundary.

**Rationale**:
- Platform-agnostic design allows use across different agent platforms (Claude Code, Copilot, Cursor)
- MCP SDK's `CallToolResult` includes extra fields (`isStreaming`, `_meta`) not needed for simple output
- Decoupling enables future non-MCP agent tool integrations
- Simpler interface for plugin authors

**Alternatives Considered**:
- Using MCP SDK types directly: Tighter coupling, less portable
- Generic string return: Loses success/failure semantics

### 2. Instance vs Static Methods

**Decision**: Both static methods (for convenience) and instance methods (for configuration).

**Rationale**:
- Static methods like `TerseOutput.success()` are convenient for simple cases
- Instance methods allow pre-configured verbosity for consistent behavior across a plugin
- Pattern follows Java/TypeScript conventions for utility classes

**Example Usage**:
```typescript
// Static - quick one-off
return TerseOutput.success('Done.');

// Instance - configured
const output = new TerseOutput({ verbosity: Verbosity.VERBOSE });
return output.success('Done.');  // Respects verbosity
```

### 3. Error Context Serialization

**Decision**: `JSON.stringify(context, null, 2)` with fallback for circular references.

**Rationale**:
- Agents parse JSON easily (agent-first ergonomics)
- 2-space indent balances readability with token efficiency
- Consistent format across all error contexts
- Circular reference handling prevents crashes

**Implementation**:
```typescript
function serializeContext(context: unknown): string {
  try {
    return JSON.stringify(context, null, 2);
  } catch {
    return String(context);
  }
}
```

### 4. Verbosity Level Semantics

| Level | Success Output | Failure Output |
|-------|---------------|----------------|
| TERSE | Short message only | Full details |
| NORMAL | Short message + summary | Full details |
| VERBOSE | Full output | Full details |

**NORMAL Mode Summary Examples**:
- Git commit: "Committed successfully. (3 files, +45/-12 lines)"
- Build: "Build completed. (12 files compiled in 2.3s)"
- Tests: "All tests passed. (42 tests in 1.2s)"

### 5. ExecResult Interface Design

**Decision**: Minimal interface defined in this package.

```typescript
interface ExecResult {
  exitCode: number;
  stdout: string;
  stderr: string;
  shortMessage?: string;  // Optional summary for success case
}
```

**Rationale**:
- Self-contained, no external dependencies
- Callers map from their execution library (execa, child_process, etc.)
- `shortMessage` is optional - callers provide it for NORMAL verbosity support

## Implementation Patterns

### Pattern 1: Factory Functions

Static methods act as factory functions for common cases:

```typescript
class TerseOutput {
  static success(message: string): TerseToolResult {
    return { success: true, output: message };
  }
}
```

### Pattern 2: Configuration Inheritance

Instance configuration can be partially overridden:

```typescript
const output = new TerseOutput({ verbosity: Verbosity.TERSE });
// Override for specific call
output.success('Done.', { verbosity: Verbosity.VERBOSE });
```

### Pattern 3: MCP Boundary Conversion

Conversion happens at the MCP server layer, not in tools:

```typescript
// In tool implementation
return TerseOutput.success('Done.');

// At MCP boundary (in server)
const mcpResult = toMcpToolResult(terseResult);
```

## Edge Cases

### Circular References in Context

```typescript
const obj = { a: 1 };
obj.self = obj;  // Circular

TerseOutput.failure(new Error('Failed'), obj);
// Fallback to String(context) or "[Circular]" placeholder
```

### Very Long Success Messages

```typescript
const output = new TerseOutput({ maxSuccessLength: 100 });
output.success('This is a very long message...');  // Truncated with "..."
```

### Missing shortMessage in ExecResult

```typescript
TerseOutput.fromExec({ exitCode: 0, stdout: '...', stderr: '' });
// Uses default: "Completed successfully."
```
