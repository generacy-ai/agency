# Implementation Plan: McpClientService

**Feature**: McpClientService for MCP connection management
**Branch**: `050-tg-011-us2-mcpclientservice`
**Status**: In Progress

## Summary

Implement `McpClientService` - a singleton service that manages MCP (Model Context Protocol) client connections to dev containers. The service provides connection lifecycle management, tool listing/execution, connection status events, and auto-reconnect functionality.

## Key Interfaces

### McpClientService Interface
```typescript
interface McpClientService {
  // Connection management
  connect(options: McpConnectionOptions): Promise<void>;
  disconnect(): Promise<void>;
  isConnected(): boolean;
  getConnectionStatus(): McpConnectionStatus;

  // Tool operations
  listTools(): Promise<ToolInfo[]>;
  executeTool(name: string, params: unknown): Promise<ToolResult>;

  // Events
  onConnectionStatusChange: Event<McpConnectionStatusChangeEvent>;
}
```

### Connection Types
```typescript
interface McpConnectionOptions {
  containerId: string;
  command?: string;
  timeout?: number;
}

type McpConnectionStatus = 'disconnected' | 'connecting' | 'connected' | 'reconnecting' | 'error';

interface McpConnectionStatusChangeEvent {
  previousStatus: McpConnectionStatus;
  newStatus: McpConnectionStatus;
  error?: Error;
  timestamp: number;
}
```

## Implementation Strategy

1. **Singleton Pattern**: Use same pattern as ConfigService
2. **Event Emitter**: Custom EventEmitter for status changes
3. **Auto-Reconnect**: Configurable retry with exponential backoff
4. **MCP SDK Integration**: Use @modelcontextprotocol/sdk Client with StdioClientTransport
5. **Dependency Injection**: Accept transport as parameter for testability

## Dependencies

- `@modelcontextprotocol/sdk`: MCP protocol client
- `execa`: Process spawning for docker exec (used by transport layer)
- Internal: `ToolInfo`, `ToolResult` from types/tool.ts
- Internal: `ContainerInfo` from types/container.ts
