## Summary

## Migrate tool schemas from contracts repo

The `@generacy-ai/contracts` repo contains tool-related schemas that belong in agency. Agency owns tool execution, so tool schemas and their generation scripts should live here.

### Background
- Contracts repo has ~1,152 exports across 209 TS files
- No active repo currently depends on `@generacy-ai/contracts` (humancy had a `file:` dep but is deferred)
- This is a "move types to their proper home" migration, not a live dependency swap

### Types to migrate into agency

**1. `src/schemas/`** — Tool and platform schemas
- `tool-naming/` — Tool naming conventions and schemas
- `tool-result.ts` — Tool result schemas
- `extension-comms/` — Extension communication schemas
- `github-app/` — GitHub App schemas
- `platform-api/` — Platform API schemas
- `knowledge-store/` — Knowledge store schemas
- `learning-loop/` — Learning loop schemas
- `decision-model/` — Decision model schemas
- `attribution-metrics/` — Attribution metrics schemas
- `data-export/` — Data export schemas

**2. `src/generated/`** — Generated JSON schema files
- Migrate the generation scripts (e.g., `generate-tool-result-schema.ts`) to agency
- Regenerate output files from the new location rather than copying generated artifacts

### Approach
- Organize by domain following agency's existing conventions (e.g., `src/tools/schemas/`, `src/platform/`)
- Migrate Zod schemas and runtime validation alongside types
- Migrate tests alongside their types (adapt to agency's vitest conventions)
- Migrate schema generation scripts and update their paths

### Acceptance criteria
- All tool schemas, platform schemas, and generation scripts from contracts are in agency
- Generated schemas can be regenerated from the new location
- Tests pass for migrated types

### Context
Replaces cross-repo issue generacy-ai/generacy#246. Latency has a separate issue for shared/cross-component types migration.
